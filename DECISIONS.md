# Questions and assumptions log

Questions that came up while building. For each I took my best guess and moved on. Change any of them and I'll adjust.

| # | Question | Decision taken | Why / how to change |
|---|---|---|---|
| 1 | Should dependencies move dates? | **No.** Links only flag conflicts (red arrow + Issues). There is no auto-scheduling. | You asked for this explicitly. A "Fix" button could be added later. |
| 2 | What are dates stored as? | `start` and `finish` as inclusive `YYYY-MM-DD` text. Duration is derived as Mon–Fri working days. | It's what people type into spreadsheets, and it avoids timezone bugs. There are no holiday calendars yet. |
| 3 | What duration does a new task get? | It starts on the selected task's start (or today, moved to the next weekday) and lasts 1 working day. | Matches MS Project's default of 1 day. |
| 4 | Do dragged bars snap to working days? | **Moving** a bar keeps its working-day duration and snaps a start that lands on a weekend to the nearest weekday in the direction of the drag (Friday when dragging back, Monday when dragging forward). **Resizing** snaps to calendar days, so you can put an edge exactly where you drop it. | A 4-day task stays 4 days when moved. |
| 5 | Can a summary task have its own dates? | No. They always roll up from the children. A task that loses its last subtask keeps the dates, % and status it showed as a summary (and stops being a milestone). | Same as Smartsheet and ServiceNow. |
| 6 | How is summary % complete calculated? | Weighted by working-day duration across leaf tasks. Milestones carry no weight. If every weight is 0, it's a plain average. | Same as MS Project, Smartsheet and ServiceNow. |
| 7 | How is summary status derived? | All Done → Done; else any Blocked → Blocked; else any started → In progress; else Not started. | Simple and explainable. |
| 8 | Which status values exist? | Not started, In progress, Blocked, Done. Setting Done sets 100%; setting 100% sets Done; going from Done back to below 100% sets In progress, or Not started at 0%. | Easy to read when sharing a plan. |
| 9 | How do predecessors refer to other tasks? | By **WBS number** in the Predecessors cell (`1.2FS+3d`). The links themselves are stored by task id, so moving tasks doesn't break them. | The ID column is hidden, and WBS is what people talk about. |
| 10 | Are links to or from summary tasks allowed? | Allowed (as in MS Project). Not allowed between a parent and its own child. | |
| 11 | Can a team be Accountable? | Allowed, with an *info*-level note. | The guidance says "a person", but monday and ServiceNow let a group own work. |
| 12 | How do RACI roles inherit? | A task with no A inherits the nearest parent's A for warnings and display, shown as "(inherited)". Nothing is copied. | Avoids flooding the plan with warnings on small subtasks. |
| 13 | Can one party have two roles on a task? | No. One letter per party per task. | Standard RACI matrix cell. |
| 14 | Are people/teams per project? | They're shared across every project in the file. | One team, many projects. |
| 15 | Can teams contain other teams? | No. Teams contain people only. | Kept out of scope by the report. |
| 16 | Multi-row selection? | One row at a time for indent/outdent/move/delete. | Keeps keyboard handling simple. Could be added later. |
| 17 | Import "update" mode: what does it change? | Rows whose ID matches a task in the current project update the mapped fields only. Unmatched rows are added. Hierarchy changes in the file are **ignored** for existing tasks. | Moving existing tasks from a spreadsheet is error-prone. |
| 18 | How are unknown names handled on import? | The value-mapping step offers: create person, create team, map to an existing person/team, or ignore. The default is "create person". A `team:` prefix forces a team. | Same as Jira and monday. |
| 19 | How are ambiguous text dates (03/04/2026) read? | You choose MDY or DMY in the wizard. It defaults to MDY unless a first part is greater than 12. | Your locale is likely US. |
| 20 | Can old browsers like Firefox or Safari be used? | They can open and export only. Saving needs Chrome or Edge. | File System Access API. |
| 21 | Where's the collapse state kept? | In localStorage per project. It isn't saved in the .db. | Each viewer chooses their own. |
| 22 | Is there a workday calendar? | Mon–Fri. No holidays. | Out of scope for v1. |
| 23 | What happens to `PRAGMA foreign_keys` after a save? | sql.js `export()` closes and reopens the database, which resets pragmas, so the app turns `PRAGMA foreign_keys=ON` back on after every export. | A technical gotcha, noted here so it doesn't get lost. |
| 24 | How does undo work? | Before each change the whole database is snapshotted, up to 40 steps. Undo restores the snapshot under a **new** revision number, so saving and recovery stay consistent. | Simplest correct approach at this data size. |
| 25 | How many tasks can it handle? | Rows are virtualized, so it should stay smooth up to a few thousand tasks. | |
| 26 | Which ID is exported? | The internal task id goes into the export ID column, so re-importing in update mode matches rows exactly. | Makes "send the spreadsheet out, get updates back" work. |
| 27 | What does outdent do to the tasks below? | Later siblings become children of the outdented task, so the visible row order never jumps. | Same as MS Project and Smartsheet, where the outline is a positional list. |
| 28 | What if a move or indent puts a linked task under its own predecessor? | The link between parent and child is removed automatically, with a short message. | Those links aren't allowed (#10), and they'd show as a conflict that can never be fixed. |
| 29 | What about two people editing copies of the same .db, or two tabs? | Not supported: one editor, many viewers. **Only one tab can edit:** the first tab holds a browser lock, and any other tab opens read-only with a banner and a *Take over editing here* button (the old tab then turns read-only). A plan is identified by the random file id inside it, not by its file name. On start or Reconnect the app compares the file with the browser copy, knowing which revision the file last held: if only one side changed, that side wins; if both changed, the higher revision wins (the file on a tie) and the other side is kept as a backup (#64). A different plan in the file always wins over the browser copy, which is backed up. The two versions are **not** merged. | Merging is out of scope (see the report). Browsers without Web Locks only get a warning. The save log records what happened. |
| 30 | Do pickers save when you click away? | Yes. Clicking outside the people picker saves your ticks. Esc cancels. | Losing ticks silently felt worse than saving them. |
| 31 | When does import default to "Update current project"? | Only when the workbook was exported from **this same .db file** (matched by a random file id saved in the file) **and** the same project. Otherwise it defaults to "Create a new project". | Task ids restart at 1 in every file, so matching ids across files could overwrite the wrong tasks. |
| 32 | Is CSV export protected against Excel formula injection? | Yes. Text starting with `=` `+` `-` `@` gets a leading apostrophe, which re-import removes. | Standard protection, since task names can come from anyone. |
| 33 | How are `0.5` / `1` read in a % column? | If every number in the column is between 0 and 1, the column is read as fractions (so 1 = 100%). Text like `50%` is always read as written. | Excel's General format stores 100% as 1. |
| 34 | How does import decide something is a milestone? | If a Type column is mapped, it alone decides. Otherwise a duration of exactly 0 does. Part-day durations (`0.25d`) count as 1 day. | Stops weekend-only tasks, and MS Project's quarter-day tasks, from turning into milestones. |
| 35 | How are names separated in RACI cells? | Export uses `; `. Import splits on `;` or newlines when the cell contains them, otherwise on commas. Re-importing our own export splits on `;` only. | Lets names like "Smith, John" survive a round trip. |
| 36 | What does update-mode import change for dates? | Only the date fields the sheet provides. Start only keeps the task's working-day duration; Duration only keeps its start. Status and % go through the normal edit rules. | Never wipe dates the sheet didn't mention. |
| 37 | What happens to links when update-mode import runs? | It replaces only links between tasks that are both in the sheet. Links from rows the sheet doesn't include survive. | Teammates often delete rows that don't concern them before sending a sheet back. |
| 38 | Where does the record form open? | A **left-hand panel, a third of the window wide (at least 420px)**. It pushes the WBS outline to the right, and the Gantt keeps its place, so the outline's right-hand columns slide under the Gantt. Clicking a row or a bar switches records. Close it with ✕, Esc or Ctrl+I. | You asked for this (three rounds of feedback). |
| 39 | Can notes be edited and deleted? ServiceNow work notes can't be. | **Yes**, because you asked to be able to edit them. An edited note shows "(edited)" with the time on hover. Deleting asks for confirmation and can be undone. There's no edit history beyond undo. | Your request comes before SN fidelity. Notes could be made append-only later by hiding Edit and Delete. |
| 40 | How are related records built so RAID can be added? | A list of tabs (`RELATED_TABS` in `45-form.js`), each with a label, a count and a render function. RAID is a "soon" placeholder that shows the planned columns: Type, Number, Short description, State, Owner, Due. | Adding RAID becomes a new table plus one tab entry. |
| 41 | Who wrote a note? | Notes show **no name**: a small blank person avatar, the date and the yellow work-note bar. The database keeps an optional `author` column (empty for now), so names could come back later without a migration. | You said a name isn't needed. |
| 42 | Are notes included in Excel export and import? | Export adds a **Notes** sheet (task id, WBS, task, created, edited, note; oldest first; local time). Import ignores it, and CSV export has no notes. | The sheet is for reading and sharing. Merging notes on re-import would risk duplicates. |
| 43 | How are note timestamps stored? | UTC ISO 8601 (`2026-11-01T14:05:00.000Z`), shown in the viewer's local time. | Sorts correctly, and teammates in other time zones see their own local time. |
| 44 | What does the mini Gantt show? | Direct subtasks by default; "All levels" shows the whole subtree in outline order, up to 80 rows. It's always scaled to fit the pane, with no grain buttons. Bars are read-only (no dragging), and clicking one opens that record. | It's a quick view. Detailed date editing stays in the main Gantt. |
| 45 | Does a parent show its children's notes? | Yes by default, labelled "on 1.2 Wireframes". A toggle shows the parent's own notes only. The setting is remembered per browser. | Lets a PM read the whole work package's story in one place. |
| 46 | Is the task "Notes" field the same as work notes? | No. The old free-text `notes` column is now labelled **Description** in the form. Work notes are the separate dated journal. The Excel column keeps the name "Notes" so older exports still import. | It matches SN's Description field vs work notes. |
| 47 | Should field changes ("State: Done (was In progress)") appear in the stream, as in SN? | Not now. You asked for a stream "made only of notes". | Could be added later from the undo/save log. |
| 48 | How does "Responsible same as Accountable" work? | It's a switch per task, stored as `task.r_is_a` (schema v3). When it's on, Responsible shows the task's effective Accountable, including one inherited from a parent. Any separate R entries are removed, because a party can hold only one letter per task. The RACI matrix shows `A/R` (or `a/r` when inherited), and export writes the Accountable into the Responsible column. Choosing a Responsible anywhere turns the switch off. On import, a Responsible column equal to the row's own Accountable turns the switch back on; one equal only to an inherited Accountable stays as Responsible entries. | A common RACI shorthand ("A/R") that doesn't break the one-letter-per-party rule. |
| 49 | Which fields go side by side on the record? | Two columns, labels above the fields: Name (full width); Type / Status; Start / Finish; Duration / % complete; Accountable / Responsible (with the switch); Parent / WBS code; Description (full width). | Each row is one idea: what and its state, when, how long and how far, who, where. Labels above fit two columns into a third of the screen. |
| 50 | How wide is the Gantt by default? | A third of the window, with the outline taking two thirds, until you drag the splitter, which is then remembered. With the record panel open, it's one third each: panel, outline, Gantt. | You asked for this. |
| 51 | What is the risk model? | **Risk → mitigants → tasks.** A risk is Accepted (with a reason) or Mitigated by its mitigants. A mitigant is implemented by tasks. No other RAID types yet. | You're focused on risks first. Research is in `reports/RAID relationships.md`. |
| 52 | What relationships exist? | Only **mitigant implements task**, many-to-many, stored in `mitigant_task`. There are no "affects" or "tests" links. | You asked for implements only. Testing is a text field on the mitigant. |
| 53 | How is a mitigant's status set? | Not started → Planned → Implemented → Tested. With linked tasks, it's Planned until every linked task is Done, then Implemented. Tested is always set by hand, and only counts once every linked task is Done (until then the mitigant shows Planned with a gap). Without tasks, the status you pick applies. | The plan drives the status, so it can't drift from reality. Tested needs a human. |
| 54 | When is a mitigant "achieved"? | At Implemented for a one-off, at Tested if the **Control** box is ticked. A risk is **Mitigating** until every mitigant is achieved, then **Mitigated**. Accepted risks need no mitigants. | Doing a control doesn't prove it works. There's no "not mitigated" state during the project: the closeout shows ✗ instead. |
| 55 | Who owns a risk or a mitigant? | Both have Accountable and Responsible, with the Same-as switch, like tasks. A mitigant with no Accountable shows the risk's (inherited). A party holds only one of R or A on a record. | You asked for this. |
| 56 | How is a pasted plan split into mitigants? | One per line or bullet when there are several lines; otherwise "1. … 2. …" numbering; otherwise one per sentence (".", "!", "?" or ";" followed by a capital or digit), without splitting after abbreviations like "e.g.". You review and edit the lines before they're added. The original plan text is kept on the risk. | Good enough for typical registers, and the review step catches odd cases. |
| 57 | What does ＋ Task create? | A task named "Implement: <mitigant>" (shortened to 80 characters), under the parent you last used for this, else a top-level **Risk mitigation** summary task (created if missing). It's linked, and it gets the mitigant's Accountable/Responsible. Dropping between two tasks puts it exactly there. | Fast, and keeps mitigation work together unless you place it elsewhere. |
| 58 | How do risk ids, numbering and import work? | Ids are internal and not shown, since you care about names. Import adds risks to the current project, matches owners by name case-insensitively (a `team:` prefix makes a team), treats 1–5 values as 1–2 Low, 3 Medium, 4–5 High, and treats "accept" in a response column as Accept. | You asked for this. |
| 59 | Where do notes on risks and mitigants go? | The same `note` table, now with `risk_id` and `mitigant_id`. A check makes each note belong to exactly one task, risk or mitigant. Upgrading a file rebuilds the table and keeps existing notes. | One journal format everywhere. |
| 60 | How many teams can a person be on? | **One** (their home team). Adding someone to a team moves them out of their old one, with a message. A person's edit form has a Team field. | You said one is fine for now. It keeps the team rollup free of double counting. |
| 61 | How does the RACI matrix work by team? | **By team** is the default (switchable to By person, remembered). Columns are teams. A cell shows the team's own role in bold plus each member's role as a small chip (e.g. `R·CP`), using their home team. Clicking a cell cycles the team's own role (— R A A/R C I). The **+** in the corner hands that role to a member (the team's role moves to the person), or assigns a member a role when the team has none. People without a team get a display-only "No team" column. Task names open the record panel beside the matrix. | Your design: program-level view by team, in-the-weeds detail one click away. |
| 62 | Is a shared .db file trusted? | **No.** On opening, the app refuses SQLite files that aren't Offline PM plans (without changing them), refuses files whose tables don't have the expected layout, drops any triggers or views it didn't create, and repairs values the screen relies on (numbers, fixed words like R/A/C/I, links to missing rows), saying how many rows it repaired. Every value is escaped when shown, and the page has a Content-Security-Policy: only its own scripts run and it can't reach the network. | A plan passed between teammates could otherwise run code that rewrites the plan file or sends it somewhere. The policy's script hashes are computed by `build.ps1`. |
| 63 | Does Save a copy make a new plan? | **Yes.** The copy gets a new random file id, so an Excel export from one never defaults to updating the other (#31). Undo and redo never bring back an earlier file id. | Task ids are numbered per file, so the two copies drift apart as soon as either is edited. |
| 64 | What happens to work the app has to replace? | It keeps a copy first, in this browser: a browser copy that lost to the file, an unsaved plan replaced by New or Open, a file version overwritten by newer browser work, or a browser copy that couldn't be opened (made by a newer version, say). File → *Recover replaced copies* lists the newest 3 and downloads them as .db files. If the browser copy can't even be read, the tab opens read-only so it isn't overwritten. | "Higher revision wins" used to throw the other side away silently. |
| 65 | When does a milestone happen within its day? | At the **end** of the day, like MS Project's 5 pm finish. A milestone on the day its predecessor finishes is not a conflict; a successor of a milestone starts the next working day. The Gantt draws the diamond on the day's right edge so arrows match. | Placing "Go-live" on the last day of UAT is the usual way to plan, and it used to be flagged. |
| 66 | Which circular dependencies are refused? | Besides loops of links, any link that can't be met because a summary task spans its subtasks: e.g. C → Y when P contains C, then Y → P. Indent, outdent and drag-moves that would create such a loop are refused too, with a message to change the links first. | These used to be accepted and left a red conflict that could never be fixed. |
| 67 | How does update-mode import handle odd IDs and files? | IDs must be whole numbers ("12b", "1.9", "1,234" match nothing and are added as new rows). If two rows share an ID, only the first updates that task; the rest are added as new tasks, with a warning in the preview. Updating from a workbook that wasn't exported from this plan and project, or from any CSV, needs a tick to confirm. A CSV that isn't valid UTF-8 is read as Windows-1252. | A copied row, a sheet from another plan, or Excel's ANSI CSV used to overwrite or garble tasks silently. |
| 68 | What if writing the file fails? | The write is retried after 2, 5, 15, 30 and then every 60 seconds until it succeeds (a lost permission isn't retried: it needs Reconnect). Closing the tab warns while the file is behind. New plan file and Save a copy refuse to overwrite the file the plan is already saved in. | Antivirus and sync clients briefly lock files; accepting Chrome's "Replace?" for the open file used to wipe it. |
| 69 | What else does import check before it writes? | Predecessors are resolved in the preview, so ones that can't be found are listed before importing; in update mode such a row keeps its existing links. Step-3 choices (ignore, map to someone) also apply to the People sheet, and a person already on a team isn't added to another. Only the cells a sheet really has are read (at most 100,000 rows × 300 columns). Column guesses prefer the main name ("Start" over "Baseline Start", "Task Name" over "Description"), and date-like headers are never "% complete". Status or people values like "constructor" are ordinary text. | Each of these used to lose data silently, abort the import, or freeze the tab. |
| 70 | What does CSV export do to line breaks and formula-like text? | All line breaks become plain newlines (a lone carriage return would split the row). Text starting with = + - @, a tab or a carriage return gets a leading apostrophe; re-importing a CSV removes it again, notes included. Excel files aren't changed. | Extends #32. |
| 71 | What happens to an edit the app refuses, or a drag you change your mind about? | A refused cell edit (a bad date, finish before start) keeps the editor open with what you typed. Starting a Gantt drag first saves any open edit. Escape, or switching to another window, cancels any drag (rows, bars, links, risks) and puts things back. | Typed text used to vanish, and a drag could write old dates over an edit made a moment before. |
| 72 | How does the outline work from the keyboard and with a screen reader? | Tab and Shift+Tab still indent and outdent the selected task (as in MS Project), and so do Alt+Shift+→ and ←. Esc clears the selection, after which Tab moves on out of the outline. The outline is announced as a tree grid (level, expanded, selected), and it shows a focus ring when reached by keyboard. Dialogs take focus, keep Tab inside, and hand focus back when they close; messages are announced. Avatar colours are dark enough for white initials at every hue. | Keyboard users could never Tab out of the outline (WCAG 2.1.2). |
| 73 | Do risks survive Excel export and import? | Yes. Plan export adds a **Risk register** sheet (one row per risk: ID, name, description, mitigation plan, response, reason accepted, probability, impact, Accountable, Responsible) and a **Mitigants** sheet (one row per mitigant: ID, the risk's ID, text, control, status, the IDs of its tasks, Accountable, Responsible, testing, handed to). The closeout report goes along as **Risk closeout**, for reading only. Plan import reads the first two from our own workbooks. In Update mode risks and mitigants are matched by ID within the project and updated; a blank or unknown ID adds one, and nothing missing from the sheet is deleted. A mitigant's task links are replaced by the ones in its Tasks cell. **Status** is the status set by hand, so with tasks linked it's blank or Tested (#53). People follow the task rules (#48), and names on risks are matched in step 3 like names on tasks. A missing column leaves that field as it is. | A risk with several mitigants needs two sheets: on one sheet the risk would repeat on every mitigant row, and edits to one copy would conflict with the others. Task links go in one cell, as predecessors do. |
| 74 | How is markup built? | One way only: the `html` template tag escapes every `${value}` unless it's another `html` result (or a list of them). `setHtml()` and `h(..., { html })` accept only those results, and joining two results with `+` throws, so a plain string can't reach `innerHTML`. Escaping by hand with `esc()` is gone. | Every view had its own string building with hand-placed `esc()` calls; the reviews kept finding the one that was missed (#62). Now forgetting is impossible rather than unlikely. |
| 75 | How do views get redrawn? | Code says what went stale with `redraw("rows")`, `redraw("form")` and so on, and one function, `drawNow()`, decides what the current view shows of it and draws that once, in a fixed order (header bits, outline, Gantt, the page's own view, then the record panel). It runs in a microtask straight after the code that asked, so several requests from one click or keystroke cost one draw, and it still runs in a background tab. Code that reads the new DOM at once (opening a cell editor, auto-scroll hit tests, rescaling the Gantt, switching views) calls `drawNow()` itself. The `render*` functions only draw; nothing outside `drawNow()` calls them. | Calls to individual render functions were spread over 60 places, each choosing its own subset (some forgot the record panel, some drew twice), and a render inside another render needed special guards. The console/test API (`PM.*`) finishes drawing before it returns. |
| 76 | Where does focus go when a view redraws under it? | Back to the same control in the new markup. `markFocus()` remembers it by its `data-*` attributes under its nearest marked ancestor; a control without any, by its place among the same tags in that ancestor (a risk row's second person button); otherwise by its text. It keeps the caret and any typing not yet saved. If the match is missing or ambiguous, focus isn't moved rather than landing on the wrong button. While Tab is moving focus, queued redraws wait until it lands, because rebuilding then would remove the element focus is headed for. The record panel no longer blurs a field after every change. While a text field there has focus it refreshes the other fields in place; a dropdown change, or a change of layout (task to milestone), rebuilds it, keeping focus. Typing never carries over to another record. | Tab out of a record field, or changing a dropdown by keyboard, used to drop focus on the page body, as did Tab between cells on the Risks page. |
